# Звук готовности Handy

На Fedora играет тихий мягкий тон, когда Handy успешно записал распознанный
текст в буфер. Слышен и при работе в окне Debian. Доставку буфера в VM
сервис не проверяет; используется уже настроенный общий буфер.

Нужен режим Handy `Copy to Clipboard`. Рекомендуемый Paste Method — `None`.
Микрофон, хоткей, модель и настройки Handy сервис не меняет.
Новые системные пакеты и права ввода не нужны.

Сигнал длится 0,4 секунды, плавно начинается и затухает. Установщик создаёт
`~/.local/share/sounds/handy-ready.wav` скриптом `make-ready-tone.py`;
пиковая амплитуда ограничена примерно 10% цифровой шкалы. Итоговая громкость
также зависит от громкости системы. Сгенерированный WAV в Git не хранится.

## Установка

```bash
bash handy/install-ready-sound.sh
```

Сервис запускается при входе в графическую сессию. Читает только новые строки
`~/.local/share/com.pais.handy/logs/handy.log`; старые результаты не озвучивает.
Вращение журнала и его усечение поддерживаются. Содержимое буфера не читает,
тексты диктовки не сохраняет и не выводит в журнал сервиса.

Источник события проверен по Handy 0.10.1: `Text pasted successfully in ...`
в `src-tauri/src/actions.rs` появляется после успешного `utils::paste`, который
в режиме `Copy to Clipboard` включает запись в буфер. Это DEBUG-сообщение;
оно присутствует в журнале установленной сборки. Если будущая версия изменит
сообщение или отключит DEBUG-журналирование, сервис потребует адаптации.

Основа подхода — workaround из обсуждения:
https://github.com/cjpais/Handy/discussions/666
Здесь используется более позднее событие успешного вывода, один постоянный
процесс вместо нового `tail` на каждое нажатие и поддержка смены журнала.

## Проверка

```bash
systemctl --user status handy-ready-sound.service
~/.local/bin/handy-ready-sound --test-sound
```

Затем надиктуй короткую фразу: звук должен прозвучать после обработки,
когда текст доступен для ручной вставки. Обычное копирование текста
и неудачное распознавание сигнала не вызывают.

## Отключение

```bash
systemctl --user disable --now handy-ready-sound.service
```

Handy продолжит работать без дополнительного звука.
